# 게이트 실행

커널이 결정적 레인을 돌리고, 판정이 필요한 것만 요청 파일로 남긴다.
네 일은 **그 요청을 판정자에게 넘기고, 다시 돌려서 결론을 내는 것**이다.

## 절차

### 1. 실행

```bash
npx gate run --json
```

종료 코드가 계약이다:

| 코드 | 뜻 | 다음 행동 |
|---|---|---|
| `0` | 통과 | 끝 |
| `1` | 실패 | 결함을 고친다. 게이트를 끄거나 마스크로 덮지 않는다 |
| `3` | 차단 | `broken`/`stale`/미판정/`unproven`(red 미시연)/고른 게이트 0개/선언된 룰 누락 — 사유를 보고 푼다 |
| `20` | 판정 필요 | 2단계로 간다 |
| `2` | 사용법 오류 | 명령을 고친다 |

`3` 은 결함이 아니라 결론을 낼 수 없는 상태다. 사유별로 푸는 법이 다르다:

- `unproven` — 그 룰의 `prove` 에 위반 픽스처(`expect: 'red'`)를 넣고
  `npx gate prove --rule <id>` 로 red 를 시연한다. `coverage.requireProven` 을 내리는 것은
  해법이 아니다.
- 고른 게이트 0개 — 설정의 `rules` 와 스위트의 `include`, `--rule` 철자를 본다. 빈
  스위트가 의도된 것일 때만 그 스위트에 `coverage.allowEmpty: true` 를 둔다.
- 선언된 룰 누락 — 리터럴 경로로 적은 파일이나 `required` 에 적은 id 가 없다. 파일·export
  를 되살리거나, 선언이 틀렸으면 `rules`/`required` 를 고친다.

### 2. 판정 요청 처리 (코드 20일 때만)

```bash
npx gate pending
```

각 요청마다 **`gate-judge` 서브에이전트를 하나씩** 띄운다. 여러 건이면 한 메시지에
여러 Agent 호출을 넣어 병렬로 돌린다.

에이전트에게 넘길 것은 **요청 파일 경로 하나뿐**이다. 요청 내용을 프롬프트에
풀어 쓰지 않는다 — 슬라이스는 파일에 이미 물질화돼 있고, 네가 옮겨 적으면
그 과정에서 잘리거나 섞인다.

```
.gate/judge/<key8>/<rule>.r<n>.request.json 을 판정하고
같은 디렉토리에 <rule>.r<n>.answer.json 을 써라.
```

### 3. 판정 결과를 들여보낸다

```bash
npx gate judge <rule> --verdict .gate/judge/<key8>/<rule>.r<n>.answer.json
```

커버리지 검사가 **기록 전에** 돈다. 후보 하나라도 답이 없으면 여기서 거부되고
아무것도 캐시되지 않는다 — 빠진 후보만 다시 물어 답 파일을 고친다.

에이전트가 쓴 답 파일을 손으로 고쳐 통과시키지 않는다. 그건 네가 판정한 것이다.

**너 자신이 판정하지 않는다.** 생산자와 검증자를 분리하는 것이 이 레인의 목적이고,
게이트를 만든 세션이 그 게이트를 판정하면 같은 맹점이 그대로 통과한다.

### 4. 재실행

```bash
npx gate run --json
```

판정 파일이 있으면 커널이 흡수해 결론을 낸다. `pending` 이 남아 있으면 아직
결론이 아니다 — 통과로 보고하지 않는다.

`red → green` 으로 넘어갈 때는 커널이 확인 표(`round: 2`)를 한 번 더 요구한다.
비용이 아니라 설계다: red 는 1표로 나고 green 은 2표로만 난다.

## 금지

- **게이트를 끄고 진행하지 않는다.** 게이트가 막으면 게이트를 고치는 게 아니라
  걸린 것을 고친다. 룰이 틀렸다고 판단되면 `criterion` 을 고치고 — 그러면 과거
  판정은 자동으로 `stale` 이 되어 다시 판정된다.
- **판정 결과를 산문으로 요약해서 넘기지 않는다.** 결과는 파일이다.
- **`stale` 을 통과로 읽지 않는다.** 기준·대상·탐색이 바뀌면 과거 green 은
  무효다. 재실행해서 새 판정을 받는다.
- **`broken` 을 결함 0 건으로 세지 않는다.** 판정 불가는 통과가 아니다.
- **`skipped` 를 통과로 세지 않는다.** 안 돈 게이트는 아무것도 보장하지 않는다.
- **`unproven` 을 통과로 읽지 않는다.** 결함 0 건이어도 red 를 시연한 적 없으면 초록이
  아니다. `coverage.requireProven` 을 끄는 것은 게이트를 끄는 것이다.
- **빈 선택을 통과로 읽지 않는다.** `--rule` 오타나 태그 누락으로 0개가 골라졌으면 그
  실행은 아무것도 검사하지 않았다.
- **면제로 red 를 지우지 않는다.** `gate mask` 는 판정자가 "위반 아님" 이라고 답했을
  때 쓰는 것이지, 위반을 덮는 도구가 아니다. 면제는 커밋되는 `gate.masks.json` 에
  남아 리뷰를 받는다.

## 보고

사용자에게는 상태 기호로 요약한다:
`✓ green` / `✗ red` / `~ stale` / `? unproven` / `– skipped` / `! broken`.
`unproven` 이 있으면 그 게이트는 아직 실패를 시연한 적이 없다고 함께 말한다 —
초록이 아니라 **아직 모른다**는 뜻이다.
